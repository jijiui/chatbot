# 开发流程写作指南

本指南说明“开发流程”章节应包含的内容和写作要点，帮助读者快速复现和维护项目。

## 章节建议结构
- **目标与前提**：说明开发流程要达成的目标（跑通功能、可回归、可发布）和前置条件（环境/权限/账号）。
- **分阶段流程**：按时间顺序列出阶段与关键动作，例如：
  1) 初始化：获取代码、创建虚拟环境、安装依赖、准备配置/密钥。
  2) 开发：编码、格式化、静态检查、单元/集成测试。
  3) 验证：手动冒烟或自动化测试，记录结果。
  4) 发布准备：更新文档、版本号、打 tag/包。
  5) 运行/回滚：启动/停止命令，简单回滚指引。
- **责任与输入输出**：每阶段写清责任人（或角色）、输入物（配置、脚本）、输出物（可运行版本、测试记录）。
- **命令与脚本**：提供可复制的命令（如 `pip install -r requirements.txt`、`ruff check .`、`python main.py`），注明工作目录/环境变量。
- **决策与检查点**：列出必须通过的检查（示例：lint 通过、关键用例手测通过、无敏感信息、版本号更新）。
- **注意事项与风险**：记录易错点（如需保持微信在线、节流生效、密钥不要写入代码）和处理方式。

## 写作要点
- **可执行性**：命令、路径、文件名全部具体可复制；避免模糊表达。
- **简洁分段**：每阶段用短段落+要点，避免长篇叙述。
- **与项目绑定**：引用本项目实际的脚本、配置文件名、环境要求，避免通用空话。
- **更新频率**：重大流程调整（新脚本、新检查项）时同步更新此章节，并标注日期/版本。

## 参考示例（可按项目改写）
- 初始化：`python -m venv .venv && .\.venv\Scripts\activate && pip install -r requirements.txt`；复制 `config.yaml.example` 为 `config.yaml` 填入 `api_key`、`friend_nickname`。
- 开发：编码后运行 `ruff format . && ruff check .`；必要时手动跑核心流程。
- 验证：启动 `python main.py`，用联系人 B 发送测试消息，确认正常回复与失败分支。
- 发布：更新版本号/README，提交并 `git tag v0.x.y`；推送代码和标签。
