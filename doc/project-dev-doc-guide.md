# 项目开发文档编写指南

本指南用于规范项目开发文档的结构与深度，确保团队成员和利益相关方快速理解并落地项目。

## 推荐文档结构
- **封面与版本记录**：文档名称、维护人、版本/日期、变更摘要、适用范围。
- **项目概览**：业务背景、目标与非目标、核心用户/场景、成功度量指标。
- **架构与设计**：系统边界、关键组件与数据流、接口契约、技术选型及取舍、性能与容量预估。
- **环境与依赖**：运行环境矩阵（本地/CI/生产）、硬件/云资源、第三方服务、密钥/配置管理方式。
- **本地开发与构建**：工具链版本、初始化步骤（克隆、依赖安装、环境变量示例）、常用脚本、构建与打包流程。
- **代码规范与质量**：代码风格/格式化规则、静态检查、分支策略、提交信息规范、代码评审要求。
- **测试策略**：测试金字塔定义（单测/集成/端到端）、覆盖重点、测试数据管理、如何运行与调试测试。
- **发布与交付**：版本编号、变更冻结点、构建产物、发布流水线、回滚策略、灰度/金丝雀方案。
- **部署与运行**：部署步骤、配置项说明、健康检查、扩缩容策略、SLO/SLA/SLI 定义。
- **监控与告警**：指标与日志采集、仪表盘链接、告警规则、应急联系人与当班轮值。
- **安全与合规**：身份与访问控制、数据分类与加密、隐私合规、依赖漏洞管理、审计要求。
- **数据管理**：主要数据模型、存储方案、备份与恢复、迁移策略、数据留存策略。
- **运维与支持**：日常巡检清单、常见故障及排障流程、变更管理、灾备演练。
- **风险与假设**：已知风险、假设前提、未解决问题、缓解/跟进计划。
- **术语与附件**：术语表、参考链接、API 契约、图表附件、决策记录（ADR）。

## 编写要点
- 受众优先：先写清“谁会看、要完成什么任务”，避免信息过载。
- 任务导向：每节包含具体“怎么做”的步骤或链接，而不是概念堆砌。
- 可追溯：设计取舍、性能估算、风险缓解要记录证据或测量结果。
- 单一事实源：对环境变量、接口定义、脚本命令使用表格或引用现有配置文件，避免重复。
- 可维护：设定更新频率、责任人，在封面或版本记录中标明。
- 可用性：大量操作步骤提供命令示例；长流程用流程图或序列图辅助（若适用）。

## 快速检查清单
- [ ] 关键读者能在 5 分钟内找到项目目标、入口和运行方式。
- [ ] 架构图/数据流图能覆盖核心组件和接口，且与最新实现一致。
- [ ] 本地启动、测试、构建、发布的命令均可复制运行，并指向脚本来源。
- [ ] 风险、假设、回滚/故障处理路径已写清，紧急联系人可见。
- [ ] 监控与告警的指标、阈值、仪表盘和告警渠道均已列出。
- [ ] 文档版本和最近更新日期明确，责任人可联系。
